# Three Kingdoms Duel

A hidden-role Three Kingdoms card battle (in the style of Sanguosha) for 2–8 players,
played in the browser with live video of every player at the table.

## Getting started

```
npm install                 # no lockfile is committed
npm run art:fetch           # downloads the card/hero art into public/art
cp .env.example .env.local  # then set VITE_CONVEX_URL
npx convex dev              # creates/links a Convex deployment and pushes convex/
npm run dev                 # http://localhost:3000
```

Live version: https://b46il6zznx5ht3o4st1xn6a4.macaly.app

The processed art isn't stored in git. `npm run art:fetch` copies it from the live
site; to rebuild it from the original Wikimedia Commons files, run
`node scripts/art/download.mjs` then `python3 scripts/art/process.py`.

## How it works

- **Rooms**: create a room, share the invite link (`/room?code=XXXXX`), the host deals roles.
- **Rules engine** (`convex/game/engine.ts`): server-authoritative. Clients only send
  decisions; hands are hidden per player. Every decision has a timer; when it runs
  out a scheduled Convex function applies the default (pass / end turn / discard).
- **Video** (`src/hooks/use-video-mesh.ts`): a WebRTC mesh between players, with
  offers/answers/ICE exchanged through the `signals` table in Convex.
- **Art**: crops of public-domain / CC0 works from Wikimedia Commons, generated by
  `scripts/art/*` into `public/art`. Attribution is listed on `/credits`.

## Single player

`/solo` runs the same engine entirely in the browser against 1–7 AI opponents
(`convex/game/bot.ts`). The AI only uses public information plus its own hand and
role: it reads allegiances from who attacks whom. Games in progress are saved in the
browser so a reload can resume them.

## Rules included

Roles (Lord, Loyalist, Rebel, Spy), 101-card deck: Attack, Dodge, Peach, Duel,
Dismantle, Steal, Barbarian Invasion, Arrow Volley, Peach Garden, Something from
Nothing, Negate (chainable), Indulgence, Lightning, 7 weapons, 2 armors, horses.
16 heroes with skills (Liu Bei, Guan Yu, Zhang Fei, Zhuge Liang, Zhao Yun, Ma Chao,
Cao Cao, Sima Yi, Xiahou Dun, Zhang Liao, Sun Quan, Zhou Yu, Huang Gai, Lü Bu,
Diaochan, Hua Tuo).

## Video connectivity (TURN)

Only public STUN servers are configured, which connects most home and mobile
networks. Players behind strict corporate/symmetric NATs need a TURN relay. Add one
via env vars and rebuild:

```
VITE_TURN_URL=turn:your.turn.host:3478,turns:your.turn.host:5349
VITE_TURN_USERNAME=...
VITE_TURN_CREDENTIAL=...
```

The mesh suits up to ~6 players with video on; at 7–8 consider an SFU (e.g. LiveKit).

## Tests

- `npx tsx scripts/sim.ts 1000` – randomised self-play of the engine (checks card
  conservation and stalls).
- `node scripts/e2e.mjs` – three bots play through the deployed backend.
- `npx tsx scripts/botsim.ts 1000` – all-AI games (checks for stalls and rejected moves).
